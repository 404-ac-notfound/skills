# Format honesty

Last baked: 2026-09-08 after the Batcave MK-07 card.

The user often names a file type. That is a guess. The job is the thing on the screen after it ships.

## Do this before writing

1. Name where it lives — phone card, overlay, hero, print, chat bubble, NLE timeline.
2. Name what must stay live — labels, prices, state lights, type that will change.
3. Name what the named destination can actually emit. Consumer video is almost never alpha. GIF is a color hammer. Encoded UI type goes soft on a phone.
4. If the named container fails 2 or 3, say the better split out loud. Then write to that split.

## Splits that keep showing up

- Live DOM chrome + a video plate in one well. Use when headers, steppers, or copy change. Bake the well’s own background into the plate so you do not need alpha.
- CSS/JS the existing PNG. Use when the art is already right and motion is translate, flip, idle. Perfect alpha. No model drift.
- Start frame + end frame I2V. Use when a locked-camera yaw or state change has to land on a known silhouette.
- Chroma plate → key → WebM VP9 / animated WebP. Use when they truly need a transparent file and the model cannot emit one.
- Full baked video of a whole module. Use only for a demo loop with frozen copy. Not for a live lifecycle.

## Video motion from a side-elevation still

A locked side camera cannot show a driveway 3-point turn from overhead. Honest version: silhouette compresses toward a nose or tail elevation, then expands into the mirrored profile. Do not brief an orbit unless they want a new car.

## Sync

If another UI region must fire on a beat (a light, a new row), the clip needs a known clock. Write timestamps into the factory plan. The video does not draw the other region.

## Anti-moves

- Prompting “transparent background” at a model with no alpha export.
- Encoding changeable UI type into H.264.
- Letting a video model invent a 3/4 view of a schematic that must stay itself.
